# Part 1：作业内容

本次作业要求同学们开发一个使用**前后端分离架构**的计算器系统。

可视化客户端不限制形式，可以实现为 Web 应用、Android/iOS 应用、微信小程序或其他合适的客户端。

前端主要负责用户交互与信息展示，后端负责计算、表达式处理、数据校验、异常处理以及数据库操作。

前端与后端之间应通过 HTTP/HTTPS API 等网络接口进行通信。

---

## 1. 计算器基础功能

### 功能 1：基础计算

实现计算器的基本计算功能。

至少应支持以下算术运算：

- 加法 `+`
- 减法 `-`
- 乘法 `×`
- 除法 `÷`

用户通过前端输入计算内容，前端将计算请求发送给后端。

**最终计算结果必须由后端生成并返回给前端。**

**不允许前端直接完成核心计算，然后把计算好的结果发送给后端，仅用于存储或展示。**

例如：

```text
12 + 8
```

前端可以发送类似这样的请求：

```json
{
  "expression": "12+8"
}
```

后端执行计算并返回类似这样的结果：

```json
{
  "expression": "12+8",
  "result": 20
}
```

随后前端展示后端返回的结果。

用户界面可以将乘法和除法显示为 `×` 和 `÷`，而内部表达式或 API 表示可以使用 `*` 和 `/`。

---

### 功能 2：复合表达式计算

计算器应支持复合数学表达式。

例如：

```text
1 + 2 * 3
(1 + 2) * 3
10 / 2 + 7
8 - 3 * 2
-5 + 8
3 * -2
```

后端应按照数学规则正确处理表达式，至少包括：

- 运算符优先级
- 括号
- 一元正负号，例如 `-5` 和 `3 * -2`
- 小数
- 非法表达式处理
- 除零处理

计算过程必须在后端完成。

**前端不得直接计算表达式的最终结果。**

出于安全考虑，**禁止通过 `eval`、`exec` 或其它等价的任意代码执行方式直接执行用户输入。**

> 原文：For security reasons, **direct execution of user input through functions such as `eval`, `exec`, or other equivalent arbitrary-code execution methods is prohibited.**

允许使用安全的数学表达式解析库，但禁止使用将用户表达式当作通用程序代码执行的方法。

同学们可以：

- 自行实现表达式解析；
- 使用安全的数学表达式解析库；
- 使用其它合理且安全的实现方式。

如果使用了第三方库，请在作业博客中说明该库及实现方式。

---

### 功能 3：计算历史

每一次成功的计算都应保存到**后端数据库**中。

保存的计算历史至少应包含：

- 计算表达式
- 计算结果
- 计算时间

例如：

| ID  | 表达式 | 结果 | 时间 |
| --- | --- | --- | --- |
| 1   | `1+2` | `3` | `2026-10-01 10:20:00` |
| 2   | `5*8` | `40` | `2026-10-01 10:21:00` |
| 3   | `(2+3)*4` | `20` | `2026-10-01 10:22:00` |

前端应能够获取并展示计算历史。

**计算历史必须从后端数据库读取，不能只依赖前端缓存、LocalStorage、应用内存或其它临时存储。**

刷新、重启或重新打开前端客户端，不得导致存储在后端数据库中的计算历史丢失。

> 原文：**Calculation history must be read from the back-end database and cannot rely only on front-end cache, LocalStorage, application memory, or other temporary storage.**

---

### 功能 4：删除计算历史

用户必须能够删除**指定的单条计算历史记录**。

例如，前端可以根据某条历史记录的 ID 发送删除请求，后端应从数据库中删除对应记录。

清空全部计算历史可以作为附加功能实现。

删除操作必须通过后端 API 完成，并且必须真正从后端数据库中删除对应记录。

删除之后，前端应根据后端数据库的最新状态更新所展示的历史记录，例如重新查询历史记录 API。

## 2. 前后端分离要求

本次作业的重点是前后端分离。

项目应遵循类似如下的架构：

```text
前端（Front End）
    |
    | HTTP / HTTPS API
    | JSON
    v
后端（Back End）
    |
    v
数据库（Database）
```

前端的职责主要包括：

- 用户界面展示
- 计算器按钮交互
- 表达式输入
- 发送计算请求
- 展示计算结果
- 展示计算历史
- 发送历史删除请求
- 展示后端返回的错误信息

后端的职责主要包括：

- 接收计算请求
- 校验输入
- 解析数学表达式
- 执行计算
- 处理计算异常
- 存储计算历史
- 读取计算历史
- 删除计算历史
- 返回标准化的 API 响应

**核心计算逻辑必须在后端实现。**

以下实现方式**不符合**要求：

```text
前端计算结果
        ↓
前端把结果发送给后端
        ↓
后端只负责存储结果
```

要求的实现方式应为：

```text
前端发送表达式
        ↓
后端校验并解析表达式
        ↓
后端计算结果
        ↓
后端存储计算记录
        ↓
后端返回结果
        ↓
前端展示结果
```

一个简单的验证方法是：停止后端服务。

此时前端可以继续接受用户输入并进行正常的界面交互，但**不得能够独立获得新的有效计算结果**。

> 原文：A simple verification method is to stop the back-end service. In this case, the front end may continue to accept user input and perform normal interface interaction, but **it must not be able to independently obtain a new valid calculation result**.

#### （10 分）功能 3：计算历史

实现不得只依赖前端缓存或临时内存。

> 原文：#### **(10') Feature 3: Calculation History** — Calculation history should be stored in the back-end database. The front end should be able to retrieve and display calculation history from the back end. History data should remain available after the front-end client is refreshed, restarted, or reopened. The implementation must not rely only on front-end cache or temporary memory.

---

#### （10 分）功能 4：删除计算历史

支持删除指定的单条计算历史记录。

前端应将对应的记录标识发送给后端，后端应删除对应的数据库记录。

删除后，前端应正确展示最新的历史数据。

对应数据必须真正从后端数据库中删除。

> 原文：#### **(10') Feature 4: Delete Calculation History** — Support deleting a specified calculation history record. The front end should send the corresponding record identifier to the back end, and the back end should delete the corresponding database record. After deletion, the front end should correctly display the latest history data. The corresponding data must actually be deleted from the back-end database.
