> 每一步都说明「做什么」「为什么」「怎么验证」，按顺序执行即可。

> 项目目录约定（下文的「学号」都指你的真实学号）：
> - 后端：`<学号>_calculator_backend`
> - 前端：`<学号>_calculator_frontend`
>
> 预计耗时：**40~60 分钟**（其中等待构建约 10 分钟）。

## 第 0 步：理解我们要做什么

### 目标架构

```
        用户浏览器
             │
    ┌────────┴────────┐
    │                 │
    ▼                 ▼
┌─────────┐      ┌──────────┐
│ Netlify │      │  Render  │
│  前端    │─HTTP→│  后端     │
│ 静态文件 │ JSON │ FastAPI  │
└─────────┘      └────┬─────┘
                      ▼
                ┌──────────┐
                │  SQLite  │
                └──────────┘
```

### 为什么必须分成两个平台？

因为**前后端分离**是本次作业的核心要求：

| 部分 | 性质 | 适合的托管方式 |
| --- | --- | --- |
| 前端 | 纯静态文件（HTML/CSS/JS），无需服务器逻辑 | 静态托管（Netlify / Vercel / GitHub Pages） |
| 后端 | 持续运行的服务进程，需要执行代码、读写数据库 | 应用托管（Render / Railway / 自己的服务器） |

**不能把前端文件丢给 Render 当静态站**那样不算错，但**前端必须能独立访问**——助教要先能打开前端页面，页面再去请求后端。

### 本教学使用的平台

| 平台 | 用途 | 为什么选它 |
| --- | --- | --- |
| **GitHub** | 存放代码 | 作业要求用 GitHub 提交，且两个平台都要从这里拉代码 |
| **Render** | 跑后端 | 免费、**不需要信用卡**、支持 Python、能连 GitHub 自动部署 |
| **Netlify** | 放前端 | 免费、不需要信用卡、纯静态零构建、比 Render 静态站更省事 |

> ⚠️ **不要用需要信用卡的平台**（如部分 Heroku 替代品）。Render 和 Netlify 免费层都不需要。

1. 打开 <https://github.com/signup>

## 第 2 步：把本地代码推送到 GitHub

### 2.1 先装 Git

检查是否已安装，打开 **PowerShell**（Win + X → 终端 / Windows PowerShell）输入：

```powershell
git --version
```

- 如果显示 `git version 2.x.x` → 已安装，跳到 2.2
- 如果提示"不是内部或外部命令" → 去 <https://git-scm.com/download/win> 下载安装，**一路默认下一步**即可，装完**关掉再重开** PowerShell

### 2.2 配置 Git 身份（首次使用需要）

```powershell
git config --global user.name "你的名字"
git config --global user.email "你的GitHub注册邮箱"
```

> 这两行只是给提交打上作者标记，不会上传任何隐私信息。

### 2.3 推送后端仓库

逐行执行（**每行执行完再执行下一行**）：

```powershell
cd C:\Users\Mikey\Documents\deepseek-harness\default-workspace\832401325_calculator_backend

git init
git add .
git commit -m "feat: 前后端分离计算器后端（FastAPI + SQLite）"
git branch -M main

# ⚠️ 下面这条必须先把两个占位符换成你自己的真实信息，否则推送一定失败：
#     <你的GitHub用户名>  →  你的 GitHub 用户名（登录 GitHub 后看右上角头像旁的名字）
#     <你的学号>          →  你的真实学号
# 注意：尖括号 < > 也要一起删掉，不要留在命令里
git remote add origin https://github.com/<你的GitHub用户名>/<你的学号>_calculator_backend.git

git push -u origin main
```

**举个填好的例子**（假设用户名叫 `MikeyorMike`、学号是 `832401325`）：

```powershell
git remote add origin https://github.com/MikeyorMike/832401325_calculator_backend.git
```

**怎么确认自己填对了**：执行完 `git remote add` 后，运行下面这条检查：

```powershell
git remote -v
```

输出里**不应该出现中文、尖括号或"你的"字样**。如果出现了，说明占位符没替换，用这条改掉：

```powershell
git remote set-url origin https://github.com/真实用户名/真实学号_calculator_backend.git
```

**会弹出登录窗口**：选 `Sign in with your browser`，浏览器里授权即可。若弹出的是用户名密码输入框，见下方"推不上去怎么办"。

### 2.4 推送前端仓库

```powershell
cd C:\Users\Mikey\Documents\deepseek-harness\default-workspace\832401325_calculator_frontend

git init
git add .
git commit -m "feat: 前后端分离计算器前端（原生 HTML/CSS/JS）"
git branch -M main

# ⚠️ 同样先替换占位符（尖括号也要删掉）
git remote add origin https://github.com/<你的GitHub用户名>/<你的学号>_calculator_frontend.git

git push -u origin main
```

> **两种"看起来像报错"的正常输出，别被吓到**：
>
> | 输出 | 含义 |
> | --- | --- |
> | `Reinitialized existing Git repository` | 该目录之前已 `git init` 过，只是重新初始化，不会清除提交 |
> | `nothing to commit, working tree clean` | 上次已经提交过、现在没有新改动。**这是好消息**，说明提交是完好的 |
> | `git branch -M main` 无任何输出 | 命令成功时本就静默 |
>
> 只要**没有** `fatal:` 开头的行，就说明前面几步都成功了，继续往下执行 `git push` 即可。

### 2.5 验证

刷新 GitHub 两个仓库页面，应该能看到完整文件列表，包括：
- 后端：`src/`、`tests/`、`README.md`、`codestyle.md`、`requirements.txt`
- 前端：`src/`、`README.md`、`codestyle.md`

> ⚠️ **检查 `data/` 目录没有上传**（`.gitignore` 已排除数据库文件）。如果传上去了，说明 `.gitignore` 没生效，但**不影响部署**。

### 推不上去怎么办

#### 情况一：连接超时 / 无法连接（国内最常见）

**报错样子**：

```
fatal: unable to access 'https://github.com/用户名/仓库名.git/':
Failed to connect to github.com:443 after 21090 ms: Could not connect to server
```

**原因**：`Could not connect to server` 表示 TCP 连接根本没建立——说明你的网络**阻断了 `github.com:443` 的直连**。这**不是** git 配置错误、不是仓库地址写错、更不是代码问题。

**先做一次诊断**，在 PowerShell 里执行：

```powershell
Test-NetConnection github.com -Port 443      | Select-Object TcpTestSucceeded
Test-NetConnection ssh.github.com -Port 443  | Select-Object TcpTestSucceeded
```

根据结果选择下面的方案：

---

**方案 A：你有代理软件 → 让 git 走代理（最推荐）**

先查你的代理端口：**设置 → 网络和 Internet → 代理**，看"地址"后面的端口号（常见：Clash `7890`、v2rayN `10809`、Shadowsocks `1080`）。下文的 `7890` 换成你的实际端口。

```powershell
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890

# 重新推送（若 remote add 已成功过，不要再执行那条）
git push -u origin main
```

> ⚠️ **代理软件关掉后 git 会连不上远程仓库**，此时需要清掉配置：
> `git config --global --unset http.proxy` 和 `git config --global --unset https.proxy`
>
> 若想"只对 GitHub 用代理、其他仓库不受影响"，改用
> `git config --global http.https://github.com/.proxy http://127.0.0.1:7890`

---

**方案 B：没有代理 → 用 SSH 走 443 端口**

若诊断显示 `ssh.github.com:443` 是**通**的，说明这条通道没被封，可以走 SSH：

```powershell
# 1. 生成密钥（连续回车即可）
ssh-keygen -t ed25519 -C "你的邮箱"

# 2. 打印公钥并复制全文
type $env:USERPROFILE\.ssh\id_ed25519.pub

# 3. 到 https://github.com/settings/keys → New SSH key → 粘贴 → Add SSH key

# 4. 新建 C:\Users\你的用户名\.ssh\config，内容为：
#      Host github.com
#        HostName ssh.github.com
#        Port 443
#        User git

# 5. 测试（出现 "Hi 用户名! You've successfully authenticated" 即成功）
ssh -T git@github.com

# 6. 把仓库地址改成 SSH 形式
git remote set-url origin git@github.com:你的用户名/仓库名.git
git push -u origin main
```

> **为什么 SSH 要指定 443 端口？** 默认 SSH 用 22 端口，很多校园网/公司网络会封 22。
> GitHub 提供了 `ssh.github.com:443` 作为备用入口，走 HTTPS 端口传 SSH 协议。

---

**方案 C：都不通 → 换网络或换时间**

- 换成**手机热点**试试（不同运营商的阻断策略不同）
- 部分校园网对 GitHub 限制较严，可换到家里网络
- 换个时间段（晚高峰时段限制往往更严）

---

#### 情况二：认证失败

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `Authentication failed` | GitHub 已不支持密码推送 | 用 **Personal Access Token**：GitHub → 头像 → Settings → Developer settings → Personal access tokens → **Tokens (classic)** → Generate new token → 勾选 `repo` → 生成后**立即复制**（只显示一次）→ 推送时密码位置粘贴 token |
| `Support for password authentication was removed` | 同上 | 同上 |
| `Permission denied (publickey)` | SSH 公钥没加到 GitHub | 回到方案 B 第 3 步 |

#### 情况三：其他 Git 报错

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `remote origin already exists` | 之前配置过 | `git remote set-url origin <新地址>` |
| `src refspec main does not match any` | 还没提交 | 先执行 `git add .` 和 `git commit -m "..."` |
| `Updates were rejected` | 远程仓库非空（创建时勾了 README） | `git pull --rebase origin main` 后再 `git push` |
| `failed to push some refs to ... (fetch first)` | 同上 | 同上 |
| `please tell me who you are` | 没配身份 | `git config --global user.name "名字"` 和 `user.email "邮箱"` |

## 第 3 步：部署后端到 Render

### 3.1 注册 Render

1. 打开 <https://render.com>
2. 点 **Get Started** → 选择 **GitHub** 登录（免邮箱验证，最快）
3. 授权 Render 访问你的 GitHub 仓库（可以只授权指定仓库，更安全）

### 3.2 创建 Web Service

1. 控制台点 **New +** → **Web Service**
2. 选 **Build and deploy from a Git repository** → **Next**
3. 找到并选择 `<学号>_calculator_backend` 仓库 → **Connect**

> 如果列表里没有你的仓库，点 **Configure account** → 在 GitHub 授权页把该仓库加入允许列表。

### 3.3 填写配置（关键步骤）

| 配置项 | 填什么 | 为什么 |
| --- | --- | --- |
| **Name** | `calculator-backend` | 决定最终域名，可自定义（只能小写字母、数字、连字符） |
| **Region** | **Singapore** | 离国内最近，冷启动和响应更快 |
| **Branch** | `main` | 我们推送的分支 |
| **Root Directory** | **留空** | 代码在仓库根目录 |
| **Runtime** | `Python 3` | 平台会自动识别，确认是 Python 3 |
| **Build Command** | `pip install -r requirements.txt` | 安装依赖 |
| **Start Command** | `uvicorn src.main:app --host 0.0.0.0 --port $PORT` | 启动服务，`$PORT` 由平台注入 |
| **Instance Type** | **Free** | 免费层 |

> **为什么 Start Command 要写 `--host 0.0.0.0`？**
> `127.0.0.1` 只能本机访问，云平台的外部流量必须监听 `0.0.0.0`（所有网卡）。
>
> **为什么要 `--port $PORT`？**
> 云平台会动态分配端口并通过环境变量 `PORT` 告知，写死 `8000` 会导致平台探测不到服务。

### 3.4 添加环境变量（**这一步最容易漏，漏了会构建失败**）

在 **Advanced** 区域点 **Add Environment Variable**，添加三条：

| Key | Value | 作用 |
| --- | --- | --- |
| `PYTHON_VERSION` | `3.12.0` | ⚠️ **必须加**。平台默认 Python 3.14，而 `pydantic-core` 在 3.14 缺少预编译轮子，会导致构建失败 |
| `RELOAD` | `false` | 生产环境关闭热重载 |
| `CORS_ALLOW_ORIGINS` | `*` | 先放行所有来源，第 6 步再收紧 |

> **什么是 CORS？** 浏览器规定：不同「源」（协议+域名+端口）之间发请求会被拦截。前端在 Netlify、后端在 Render，属于不同源，所以后端必须显式声明"我允许谁来访问我"。`*` 表示允许所有来源。

### 3.5 部署并等待

1. 点 **Create Web Service**
2. 页面会显示构建日志，依次经历：
   - `Cloning repository...`
   - `Installing dependencies...`（约 1~3 分钟，最慢的一步）
   - `Starting service...`
   - 出现 **`Your service is live 🎉`** 表示成功

首次构建通常 **3~5 分钟**。

### 3.6 拿到后端地址

页面左上角会显示你的服务地址，形如：

```
https://calculator-backend-xxxx.onrender.com
```

**把这个地址记下来**，第 4 步和第 6 步都要用。

### 3.7 验证后端（必做）

在浏览器依次访问（把地址换成你的）：

| 访问地址 | 期望结果 |
| --- | --- |
| `https://你的地址/api/health` | `{"success":true,"status":"ok","app":"Calculator Backend","version":"1.0.0"}` |
| `https://你的地址/docs` | 看到 Swagger 接口文档，列出 10 个接口 |
| `https://你的地址/` | `{"service":"Calculator Backend","version":"1.0.0",...}` |

**如果打不开或报错**，翻到 [附录 A](#附录-a常见报错速查)。

> 💡 **首次访问可能很慢（30~50 秒）**：免费实例闲置 15 分钟会休眠，重新唤起需要时间。**这是正常现象**，不是部署失败。

### 3.8 顺手用命令行验证一次（可选但推荐）

在 PowerShell 里实测计算接口：

```powershell
curl.exe -X POST https://你的地址/api/calculate -H "Content-Type: application/json" -d "{\"expression\": \"(1+2)*3\"}"
```

期望返回：

```json
{"success":true,"expression":"(1+2)*3","normalized":"(1+2)*3","result":"9","record":{...}}
```

> ⚠️ PowerShell 里 `curl` 是 `Invoke-WebRequest` 的别名，行为不同，所以这里写 **`curl.exe`** 强制调用真正的 curl（Windows 10+ 自带）。

## 第 4 步：修改前端配置并推送

前端代码里写死了后端地址，必须改成第 3.6 步拿到的公网地址。

### 4.1 修改配置

用记事本或 VS Code 打开：

```
832401325_calculator_frontend\src\js\config.js
```

把 `apiBaseUrl` 改成你的后端地址：

```javascript
window.CALCULATOR_CONFIG = {
  // 改成第 3.6 步拿到的地址，注意：
  //   - 必须带 https://
  //   - 结尾不能有 /
  apiBaseUrl: 'https://calculator-backend-xxxx.onrender.com',

  requestTimeoutMs: 60000,   // 保持 60 秒，适配冷启动
  historyPageSize: 10,
  searchDebounceMs: 320,
  verboseLog: true
};
```

### 4.2 同时修改 index.html 里的内联配置（**容易漏**）

打开 `832401325_calculator_frontend\src\index.html`，找到文件顶部这段：

```html
<script>
  window.CALCULATOR_CONFIG = {
    apiBaseUrl: 'http://127.0.0.1:8000',
    requestTimeoutMs: 60000
  };
</script>
```

**把 `apiBaseUrl` 也改成后端公网地址。**

> ⚠️ **为什么有两个地方？** `index.html` 里的内联配置**会覆盖** `config.js`。
> 如果你只改了 `config.js`，线上前端仍然会去请求 `http://127.0.0.1:8000`（访问者自己的电脑），
> 表现就是**页面能打开但一直提示「后端未连接」**。这是最常见的坑。

### 4.3 推送修改

```powershell
cd C:\Users\Mikey\Documents\deepseek-harness\default-workspace\832401325_calculator_frontend
git add .
git commit -m "chore: 配置线上后端地址"
git push
```

## 第 5 步：部署前端到 Netlify

### 5.1 注册 Netlify

1. 打开 <https://app.netlify.com>
2. 点 **Sign up** → 选 **GitHub** 登录并授权

### 5.2 导入项目

1. 点 **Add new site** → **Import an existing project**
2. 选 **GitHub**
3. 选中 `<学号>_calculator_frontend` 仓库

### 5.3 填写构建设置（**最容易出错的一步**）

| 配置项 | 填什么 | 为什么 |
| --- | --- | --- |
| **Branch to deploy** | `main` | 主分支 |
| **Base directory** | **必须留空！** | ⚠️ 仓库里已有 `netlify.toml` 指定了 `publish = "src"`，而它**是相对仓库根目录**的。若这里再填 `src`，Netlify 会拼成 `src/src`，构建直接失败 |

> 修复方法：把 **Base directory 清空**，然后重新部署
> （站点页面 → **Deploys** → **Trigger deploy** → **Clear cache and deploy site**）。

**为什么不需要填 Base directory？** 因为本项目的发布目录只有一个层级：
仓库根目录下有 `src/`，`src/` 里有 `index.html`。`netlify.toml` 已经用
`publish = "src"` 说清楚了，界面再填一次就重复了。

> 另外仓库的 `netlify.toml` 里还配了一条 `[[redirects]]` 规则，
> 把任何找不到的路径回退到 `index.html`，保证访问根路径一定能打开计算器。

### 问题

Render 免费实例 **15 分钟无请求就休眠**，助教验收时首次访问要等 30~50 秒，体验很差，甚至可能被误认为"项目坏了"。

### 方案一：用 UptimeRobot 定时唤醒（推荐）

1. 注册 <https://uptimerobot.com>（免费版支持 50 个监控、5 分钟间隔）

   - Monitor Type: `HTTP(s)`
   - Friendly Name: `计算器后端`

## 附录 B：原理讲解

### B.1 前后端分离到底"分离"在哪

不是"用了两个框架"，而是**职责边界清晰**：

| | 前端（Netlify） | 后端（Render） |
| --- | --- | --- |
| 跑在哪 | 用户浏览器里 | 云服务器上 |
| 存什么 | 只有静态文件 | 代码 + 数据库 |
| 会什么 | 显示界面、发请求、渲染结果 | 校验、计算、读写数据库 |
| 不会什么 | **不会做算术运算** | 不会画界面 |

**验证方法（作业原文建议的）**：把后端停掉，前端仍能点击、输入、切换主题，但**得不到任何有效计算结果**。这就证明计算确实在后端。

### B.2 为什么会有 CORS 这个"麻烦"

浏览器的安全机制：**防止 A 网站偷偷用你的登录身份去读 B 网站的数据**。

规则是「源」= 协议 + 域名 + 端口，三者任一不同即为跨域：

| 前端 | 后端 | 是否跨域 |
| --- | --- | --- |
| `http://127.0.0.1:5500` | `http://127.0.0.1:8000` | ✅ 跨域（端口不同） |
| `https://a.netlify.app` | `https://b.onrender.com` | ✅ 跨域（域名不同） |
| `https://a.netlify.app` | `https://a.netlify.app/api` | ❌ 不跨域 |

所以后端必须通过 `Access-Control-Allow-Origin` 响应头**显式声明允许哪些来源**。本项目用 FastAPI 的 `CORSMiddleware` 实现。

> **注意**：CORS 是**浏览器**的限制。用 curl 或 Postman 直接请求不受影响——所以"curl 能通但网页不行"是典型的 CORS 问题。

### B.3 为什么云平台要求 `--host 0.0.0.0 --port $PORT`

- **`--host 0.0.0.0`**：监听所有网卡。若写 `127.0.0.1`，只有容器内部能访问，平台的反向代理进不来。
- **`--port $PORT`**：平台动态分配端口并通过环境变量告知。写死端口会导致平台健康检查失败，然后判定部署失败。

### B.4 免费实例为什么会"休眠"

云厂商的免费层用"按需唤醒"来省资源：闲置时把容器停掉，有请求再启动。这就是**冷启动**——需要重新加载 Python 解释器、导入依赖、初始化数据库，耗时 30~50 秒。

**影响**：助教验收的首个请求会很慢。
**对策**：定时 ping 保持唤醒（见第 8 步）+ 前端超时放宽到 60 秒 + 博客里写明。

### B.5 为什么 Render 免费实例的数据会丢

免费实例的磁盘是**临时**的，重新部署或实例迁移时会重置，SQLite 文件随之丢失。

**对本次作业的影响**：助教验收期间如果不重新部署，数据是保留的，够用。
**要真正持久化**，有两个方向：
1. 挂载 Render 的 **Disk**（付费功能）
2. 把 SQLite 换成 **PostgreSQL**（Render 提供免费实例），需要改 `core/database.py` 和 `repository/`，业务层不用动——这正是分层架构的价值。
